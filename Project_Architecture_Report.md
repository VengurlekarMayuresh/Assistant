# RepoMind AI: Complete System Architecture & Agent Workflow Report

## 1. Executive Summary
RepoMind AI is an advanced, multi-agent conversational AI system designed to analyze, understand, and answer questions about any GitHub repository. It achieves near-instantaneous responses by aggressively caching code, dynamically building Knowledge Objects (KOs), mapping codebase dependencies via Graph databases, and utilizing a multi-node LangGraph agentic pipeline.

### Core Tech Stack
- **Frontend**: React (Vite), TailwindCSS, Lucide-React, React-Flow (for Architecture diagrams), react-zoom-pan-pinch.
- **Backend API**: FastAPI (Python), HTTPX (async GitHub API requests).
- **AI / LLM Orchestration**: LangChain, LangGraph, Google Gemini (Flash/Pro) via `langchain-google-genai`.
- **Databases**:
  - **MongoDB Atlas**: Document storage (caching raw file contents, repository metadata, generated Architecture diagrams).
  - **Qdrant Cloud**: Vector database (storing semantic embeddings of files and generated Knowledge Objects for similarity search).
  - **Neo4j AuraDB**: Graph database (mapping file dependencies, imports, and exports to establish codebase topological context).

## 2. Multi-Agent System (LangGraph Pipeline)
The core intelligence of RepoMind AI is driven by a state machine implemented via `langgraph`. The workflow is defined in `backend/app/agents/agent_graph.py` and consists of three primary AI Agents (Nodes) that pass a shared `AgentState` between them.

### Shared `AgentState`
The `AgentState` dictionary acts as the memory for the AI during a single query session. It stores:
- `query`: The user's prompt.
- `plan`: An array of steps generated by the Planner.
- `step_findings`: The analysis results of each step.
- `files_cache`: A local dict of files read during the current session to avoid re-fetching.
- `repo_id`, `file_list`, `languages`, `frameworks`: Contextual metadata about the repository.

### Node 1: The Planner Agent (`planner_node`)
**Role**: Architect the investigation and execute cache-first retrieval.
**Workflow**:
1. **Semantic Search (Qdrant)**: Before calling the LLM, the Planner searches Qdrant for previously generated "Knowledge Objects" (KOs). KOs are summaries of features previously analyzed by the AI.
2. **Cache Evaluator (LLM)**: If KOs are found, an Evaluator LLM decides if the user's query can be answered entirely from the cache. If confidence is `>= 0.75`, it skips investigation and routes directly to the Synthesizer.
3. **Graph Expansion (Neo4j)**: If the query relates to specific files found in Qdrant, the Planner queries Neo4j to find *related* files (dependencies, imports) up to a depth of 1. These related files are added to the context.
4. **Plan Generation (LLM)**: If a cache miss occurs, the Planner LLM generates a strict 2-4 step JSON plan (e.g., `["Read backend/main.py", "Analyze routing configuration"]`) targeting specific files.

### Node 2: The Explorer Agent (`explorer_node`)
**Role**: Read code, synthesize findings, and dynamically adapt the plan.
**Workflow**:
1. **File Selection (LLM)**: Given the current step, the Explorer LLM selects the single most critical file to read from the repository's file list.
2. **Read / Fetch Strategy**:
   - Checks the local `files_cache`.
   - If missing, checks the MongoDB `repository_files` collection.
   - If missing, fetches raw code directly from GitHub (`github_service.py`), then persists it to MongoDB and Qdrant.
3. **Analysis & Dynamic Expansion (LLM)**: The Explorer LLM reads the file content and extracts findings to satisfy the current step. **Crucially**, it is also instructed to identify any missing context (e.g., "I need to see `utils.js`"). It can dynamically inject new steps into the Planner's queue.
4. **Loop**: The graph loops back to the Explorer until all steps in the plan are completed.

### Node 3: The Synthesizer Agent (`synthesizer_node`)
**Role**: Compile final answer and trigger background optimizations.
**Workflow**:
1. **Response Generation (LLM)**: Takes the user query, the Planner's step list, and the Explorer's deep-dive `step_findings` (plus raw code snippets). It formats a comprehensive, highly technical Markdown response citing specific lines and files.
2. **Background Prefetching Task**: Before returning the response to the user, the Synthesizer spawns an asynchronous `run_prefetching` task. 
   - A sub-agent looks at the conversation context and guesses 1-3 files the user is *likely* to ask about next.
   - It fetches these files from GitHub in the background and silently caches them into MongoDB and Qdrant. When the user inevitably asks their follow-up question, the cache is already warm, resulting in instantaneous responses.

## 3. Database Architecture & Context Optimization

### MongoDB (Document Cache)
- **`repositories`**: Stores project metadata, total file counts, detected languages/frameworks, and a cached Mermaid string of the system's architecture to prevent costly re-generations on every tab switch.
- **`repository_files`**: Stores the raw text content of files. Drastically reduces GitHub API rate limiting.

### Qdrant (Semantic Memory)
When files are fetched, their contents (up to 500 characters) are embedded and stored in Qdrant. The system uses a `SemanticSearchService` to quickly convert user queries into vectors, finding matching files across large codebases without needing to inject the entire 1000-file repository into the LLM context window.

### Neo4j (Topological Graph)
The system parses files (like `package.json` or Python `import` statements) to build a topological map of the codebase. When the LLM decides to look at `ComponentA`, Neo4j automatically highlights `ComponentB` and `ComponentC` if they are tightly coupled dependencies, expanding the LLM's "blind spots" autonomously.

## 4. Frontend Application
- **Exploration Workspace**: A dual-pane layout featuring an Agent Chat on the left and a Tabbed Code/Architecture Viewer on the right.
- **Interactive Architecture Map**: Uses `react-zoom-pan-pinch` and Mermaid.js. The AI is strictly instructed to map Mermaid nodes to physical codebase file paths. When a user clicks a node (e.g., `[App.jsx]`), the frontend transitions to the File Tree and opens that specific file automatically.
- **Collapsible File Tree**: Dynamically builds a deeply nested, VSCode-style folder hierarchy from flat GitHub file paths.
- **Git History Module**: Integrates with the GitHub API (with boosted pagination limits) to retrieve and display recent Commits and Pull Requests for diagnostic context.

---

## 5. Summary of Agentic Capabilities
1. **Self-Healing / Fallbacks**: If an LLM returns bad JSON, regex scrubbers clean it. If GitHub rate-limits the API, raw user content URLs are used as a fallback.
2. **Predictive Caching**: The background Prefetcher agent simulates the next user prompt to warm up databases.
3. **Contextual Awareness**: By merging Vector Search (Qdrant) with Graph logic (Neo4j), the Planner Agent effectively replicates the intuition of a Senior Developer traversing a new codebase.
